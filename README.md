# Plan B：D435 单帧自动抓取链路

本文档定义本工作区中的 **Plan B**。后续提到“Plan B”，均指下面这条链路：只用底盘固定安装的 D435 完成一次 RGB-D 观察、目标选择、FoundationPose 位姿估计和抓取规划，不使用 D405，也不执行预抓后的视觉精纠偏。

对应工作区与版本：

- 工作区：`/home/arx/arx-d435-plan-b-20261119`
- 分支：`codex/d435-plan-b-20261119`
- 基线提交：`b609cb1`
- 调试入口：`http://<ROG-IP>:9983/grasp-integration.html`
- 页面选项：`D435 单帧 Plan B`

Plan B 当前只由自动抓取二级页面手动选择，不会在原 D405 链路失败时自动切换；原 D405 方案和默认选择保持不变。

## 一句话流程

```text
页面启动并取得控制权
→ D435 冻结一帧 RGB-D
→ DINO 产生候选、SAM2 分割、深度做本地选择；有歧义才调用 Qwen
→ FoundationPose 根据电池 CAD 求完整位姿
→ 用 CAD 计算夹指尖 TCP 终点 T 和 50 mm 预抓点
→ 升降到页面目标、张开夹爪，右臂保持当前关节位
→ 使用最新关节与升降反馈重新做 IK
→ 右臂一次执行“当前位置 → 预抓点 → T 点”
→ 夹爪闭合并确认夹持
→ 底盘后退 200 mm 并停车
→ 右臂回到 J1～J5=0°、J6=-90° 的运输姿态
→ 任务结束并把控制权返还 9983
```

## 页面怎么使用

1. 打开自动抓取二级页面。
2. 在“视觉链路”选择 `D435 单帧 Plan B`。
3. 设置“升降目标（rad）”。页面默认值为 `5.52`；到达判定继续复用原逻辑，即目标向下取整，例如输入 `6.6` 时达到 `6.0` 即可进入下一步。
4. “右臂预观察 Z”仍保留给原 D405 链路。Plan B 的右臂观察轨迹是 `stationary`，不会为了这个 Z 值移动右臂。
5. 确认现场安全复选框后，点击“开始实机流程”。

Plan B 只请求 D435 深度，不请求 D405；任务运行期间独占自动运动控制权。

## 完整步骤

### 0. 启动任务与控制权

页面向 `/api/battery-task` 提交：

- `vision_mode=d435`
- 页面填写的升降目标和观察 Z
- 当前 `command_epoch`
- 现场已清空确认

后端创建独立运行目录、保存本轮设置、打开 D435 深度，并向 9983 控制器申请本轮运动 token。已有自动任务或未恢复任务时不会再启动一轮。

### 1. 冻结一帧 D435 RGB-D

`observe_battery(camera=d435)` 同时保存：

- D435 彩色图、深度、点云和相机外参；
- 拍照时的右臂六轴、升降及时间戳；
- 本轮不可变的 observation ID 和场景摘要。

后续 FoundationPose、T 点和抓取线都绑定这同一帧。Plan B 不再拍第二张 D435，也不会在右臂移动后重新识别。

### 2. 本地视觉优先选择电池

当前提示词为：

```text
a rectangular drone battery pack with a protruding handle at one end, partially inserted into a drone.
```

实际顺序是：

1. Grounding DINO 产生候选框；
2. 排除固定夹爪区域候选；
3. 对候选运行 SAM2 分割；
4. 用 D435 深度确认掩膜能形成有效三维表面位置；
5. 合并同一电池的整体框和局部重叠框；
6. 本地结果明确时直接采用，记录 `path=local_candidate`；
7. 没有合格候选或候选有歧义时才进入 `path=qwen_fallback`，让 Qwen 从候选中选择，再用 SAM2 生成掩膜。

这里复用的既有本地选择条件是：DINO 分数至少 `0.30`、SAM2 分数至少 `0.85`、掩膜有有效深度；D435 多候选时，最高两项 DINO 分差小于 `0.10` 才视为有歧义并转 Qwen。本文档没有新增或修改这些条件。

### 3. D435 深度粗定位

对最终电池掩膜取有效深度点，计算电池可见表面的 `surface_base_mm`。这个点用于确认识别结果具有三维位置，也是粗定位信息；它不是最终夹取 T 点。

识别或深度定位失败时，流程停在 `observe_battery`，不会下发运动。

### 4. FoundationPose 计算完整电池位姿

`preview_battery_grasp` 直接复用步骤 1 的同一帧和步骤 2 的掩膜，加载电池 CAD：

```text
web/cad/gripper-v2/battery-print.stl
```

FoundationPose 将被遮挡、只露出一部分的电池与 CAD 配准，输出电池在 `base_link` 中的完整六自由度位姿。结果必须属于同一冻结帧，并通过 FoundationPose 现有的 `quality.status=consistent` 检查。

### 5. 从 CAD 位姿生成 T 点和预抓点

抓取几何按当前约定生成：

- `T`：CAD 中的 `tip` 参考点，也是已经标定的夹指尖 TCP 最终目标；
- 插入方向：CAD 抓取配置中的 `approach_base`；
- 预抓点：`T - 50 mm × approach_base`；
- 抓取线：从预抓点沿电池轴线前进到 T；
- 夹姿：沿 FoundationPose 得到的电池姿态，要求 J6 保持在约定的 `-90°` 附近。

此时只生成几何预览，还没有下发运动。

### 6. 粗对位规划

Plan B 的粗对位只规划两件事：

1. 升降到页面设置的目标；
2. 右臂保持拍照时的当前关节姿态。

因此 Plan B 不会根据 D435 再把右臂移动到一个新的“观察位”，也不会使用“右臂预观察 Z”做第二次观察。规划仍复用原有升降路径、中央立柱和现场检查。

### 7. 执行粗对位

执行顺序为：

1. 升降到目标的原有到达条件；
2. 发送升降停止；
3. 张开右夹爪；
4. 确认右臂仍在原关节位置并停稳。

这一阶段没有新的右臂观察运动。完成后状态进入 `COARSE_ALIGNED`。

### 8. 使用最新实机反馈规划抓取

升降完成后，`plan_battery_pick` 保留步骤 4～5 已经固定的电池位姿、T 点和抓取方向，但重新读取此刻最新的：

- 右臂六轴反馈；
- 升降反馈。

随后用现有 TCP、关节限位、IK 和路径规划计算：

```text
当前关节位 → 预抓点 → 沿抓取线到 T 点
```

这一步不重新拍照，也不运行 D405；它只用最新机器人状态更新机械臂解算起点。

### 9. 复用现有规划审核

执行前继续复用原链路已有的校验，包括：

- 冻结帧、相机标定、CAD 抓取配置和 TCP 版本未变化；
- T 点、预抓点、插入方向和坐标系仍属于同一份证据；
- 六轴 IK、关节限位、中央立柱/路径检查已完成；
- J6 与 `-90°` 的既有容差；
- 页面现场清空确认仍有效。

Plan B 没有增加一套新的容差或门控。

### 10. 一次完成预抓接近和插入

Plan B 不单独执行 `execute_battery_approach`。`execute_pick` 将已审核的连接段和插入段合并为一次右臂轨迹：

```text
当前位 → 预抓点 → T 点
```

这与原 D405 方案不同：中间不在预抓位重新观察，也不执行 XYZ/姿态视觉精纠偏。

### 11. 到达 T 点后闭合夹爪

只有机械臂轨迹参考完成、末端按现有到达策略停稳后，程序才发送一次右夹爪闭合命令。当前闭合目标是：

```text
gripper_target = 0
```

夹爪闭合期间保持本轮运动 token，不会另起控制器。

### 12. 夹持确认

`verify_hold` 读取新鲜的右夹爪反馈。当前复用的夹持确认范围为：

```text
-1.5 ≤ gripper feedback ≤ -0.5
```

通过后进入 `HOLD_CONFIRMED`；未通过则停在等待检查状态，不进入底盘后退。

### 13. 底盘后退 200 mm

当前 Plan B 的 `stow_for_carry` 不执行机械臂沿 X 抽出；它保持：

- 右臂关节不动；
- 夹爪继续夹持；
- 升降不动。

然后复用导航队友的底盘位姿、里程计、路径跟踪、代价地图和停车确认，使底盘沿当前朝向后退 `200 mm` 并停车。

### 14. 返回夹持运输姿态

底盘确认停车后，右臂回到：

```text
J1 = 0°
J2 = 0°
J3 = 0°
J4 = 0°
J5 = 0°
J6 = -90°
```

该动作保持夹爪闭合、升降高度不变，复用现有轨迹速度和六轴到达策略。到达后流程标记为 `completed`。

### 15. 清理与返还控制权

无论成功或失败，任务都会恢复本轮开始前的相机深度请求状态并尝试把自动运动控制权返还给 9983。

- 正常释放：日志显示“自动任务已退出，控制权已返还 9983”；
- 存在未清理运动收据或停止状态无法确认：任务进入 `recovery_required` 并暂时保留控制权，避免手动控制与未确认运动重叠。

## Plan B 明确跳过的步骤

与原 D405 链路相比，Plan B 明确不执行：

- 移动到 D405 观察位；
- D405 拍照、识别和深度定位；
- 第二次 FoundationPose；
- 预抓位后的第二次视觉观察；
- 预抓后的 XYZ/姿态视觉精纠偏；
- 运行中自动切回 D405。

这意味着 Plan B 更短，也不受 D405 故障影响；代价是抓取精度完全依赖那一帧 D435、D435 外参、深度和 FoundationPose 结果。

## 看日志时如何判断停在哪一步

| 日志/状态 | 含义 |
|---|---|
| `observe_battery` | D435 冻结、识别、分割或深度定位 |
| `path=local_candidate` | 本地 DINO+SAM2+深度已明确选择，没有调用 Qwen |
| `path=qwen_fallback` | 本地候选为空或有歧义，已调用 Qwen 兜底 |
| `preview_battery_grasp` | FoundationPose、CAD 位姿、T 点和预抓线 |
| `plan_coarse_alignment` | 升降规划；Plan B 右臂保持不动 |
| `execute_coarse_alignment` | 升降、升降停止、张开夹爪、停稳 |
| `plan_battery_pick` | 用最新关节/升降反馈做 IK 和整条抓取路径 |
| `execute_pick` | 当前位到预抓点、到 T 点、闭合夹爪 |
| `verify_hold` | 夹持反馈确认 |
| `stow_for_carry` | 底盘后退 200 mm 并停车 |
| `return_to_carry` | 右臂返回运输姿态 |

最近一次已核对的 Plan B 失败发生在步骤 2：本地候选未能明确选择后进入 `qwen_fallback`，Qwen 返回内容不符合结构化协议，因此在任何机械运动开始前终止。它不代表 Plan B 每轮都必须调用 Qwen。
