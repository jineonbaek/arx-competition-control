# 双 MID360S 独立 LIO 与动态融合修订设计

用户 2026-11-05 明确要求：头部存在结构晃动，禁止固定外参合并双点云、禁止共用头部 IMU。两台各用自身 IMU 做 LIO；先验证时间同步、独立 LIO、动态相对位姿，再接融合。D435 暂缓，软件不发送底盘控制命令，人工运动前先记录。

## 分阶段实现
1. 保留头部 LIO，新启底盘 LIO（旧 /dual/arm 原始数据，新的 /dual/bottom 输出）。独立世界坐标与 TF，不发布 base_link 或最终融合里程计。
2. 审计设备时间来源、点时间戳、IMU 覆盖、接收延时和时钟漂移。相近 header 不能证明硬件同步。先记录双 LIO/IMU/点云，保留 NUC 原始数据。
3. 同一时刻插值两路位姿，使用初始共同场景对齐世界坐标，计算头部相对底盘 IMU 的候选动态位姿。初始对齐只作为世界坐标 gauge，不约束以后传感器间位姿固定。候选变化同时含 LIO 漂移，不能直接当真实外参；用共同场景配准、双 IMU 角速度一致性、可观测性/退化检查进一步验证。
4. 只有时间与动态估计质量合格才引入统一估计器：以刚性底盘传感器为运动参考，动态头部位姿为单独状态；共同场景约束估计底盘轨迹及头部相对运动。不能将相关的两路 LIO 平均，不能用两路相减再逆转换制造伪独立测量。
5. 两路点云先在各自 LIO 中按本机 IMU 去畸变，再按各自采样时刻及世界对齐关系共同建图；动态头部在避障中使用随时间变化的传感器原点。失步、断流、退化时禁止其参与融合并报告降级，保留各路诊断。

## 尚缺条件
- 底盘雷达相对 C_base 的 XYZ 与参考高度未测量，不能把底盘雷达 IMU 原点冒充 C_base。
- 头部相对底盘动态 SE(3) 的独立真值尚无，静态/运动验证与共同场景约束是门槛。
- 先前静态 R/t 仅可作初始配准先验，不能用于运动中固定拼接。
- 仅有单帧/静态场景不能验证头部急停晃动；由用户人工低速移动/停稳记录验证，不要求猛烈急停。

## 替代方案
固定拼接与平均里程计均被用户排除。选择分别 LIO 后动态联合估计，按上述门槛推进；未经验证的输出仅诊断，不进入自动控制。
