# 手柄底盘接入候选

用户指定：右摇杆前后左右平移，左摇杆横向自旋，满杆传给 SDK 的目标原值为 2；使能键改为 LT（按钮 7）。

## 映射

- 右杆上/下：SDK x = +2 / -2。
- 右杆左/右：SDK y = +2 / -2。
- 左杆左/右：SDK yaw = +2 / -2。
- 死区 0.08，余下量程线性映射；斜向平移合成幅值不超过 2。
- 使用前先松开 LT 并将右杆及左杆横向回中，再按住 LT。松开 LT、输入失联、反馈过期、控制权拒绝后停车，并要求重新使能。

SDK 原值不是 m/s 或 rad/s 的承诺；SDK 内部编码/限幅仍然存在。`2` 为 setChassisCmd 前的目标上限，现有加减速斜坡保留，实际送入SDK的数值逐步达到目标。

## 实现

`teleop.py` 默认只预览，不建立 ROS 指令发布者。明确带 `--execute` 后，以 20Hz 向 `/web/gamepad/command` 发布SDK原值，并订阅底盘就绪及驱动确认。页面不提供远程启用开关。

`hardware-candidate` 候选驱动使用同一个SDK实例，新增专用手柄订阅；原 `/web/body/command` 的除2.5和0.8/0.4限值保留。手柄入口单独验证平移合成2、自旋2。所有输入仍经过同一加减速、反向制动和250ms超时停车。两个来源以250ms租约互斥；网页停车命令保持全局优先级，手柄随后必须重新使能。

部署与验证候选不需重启底盘。真正启用需要更换底盘二进制并重启；现有机体启动逻辑包含升降归零，只能在已确认最低位置、现场允许初始化后执行。不得额外启动第二个CAN控制SDK实例。

## 验证

Python：`python3 -m unittest discover -v`。
候选C++：`test_body_limits`、`test_chassis_motion`、`test_gamepad`。
真车尚需现场小幅输入测试方向、LT释放停车、接收器拔除和手柄无线断电；无线断连能否被接收器及时报告需要实测，不能仅凭摇杆静止时没有事件判断。

当前候选目录的CMake仅编译机体驱动和测试，不含机械臂构建；不能替换完整web/hardware/CMakeLists.txt。

## 双模式识别（2026-11-07）

- 自动读取唯一 `/dev/input/js*` 的 USB VID/PID、设备名称、轴代码列表和按键代码列表；完整签名匹配才接入。
- 已支持 NS（057e:2009、6轴14键）与 XINPUT（20bc:5128、8轴11键）。未知签名、变化的轴/按键布局、多手柄时显式报错，清空使能并禁止输出。
- `profiles.py` 保存两套配置；`legacy/` 保存本次改动前完整 NS server/teleop 与映射文件，原工作区 `gamepad_mapping_observed.json` 不变。
- XINPUT 左杆0/1、右杆3/4、十字6/7；LT轴2、RT轴5。扳机 joydev 值从 -32767（松开）到32767（全扣），归一化0..1；LT扣过一半使能，松开停车。
- 本次24项实测 XINPUT：Y3、B1、A0、X2、RB5、LB4、L3为9、R3为10、M1与B共用1、M2与LB共用4。BACK/START/HOME采用内核语义6/7/8，尚未逐个物理验证。
- 逻辑轴始终为左X/左Y/右X/右Y/十字X/十字Y，再按用户指定映射到SDK速度。切换模式或设备重连会更换连接标识，必须松LT回中后重新按LT，不会沿用旧使能状态。
- 控制端每次都核对已知模式；报告绑定连接标识，页面不接受旧连接的输出报告。
