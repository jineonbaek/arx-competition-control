## 1. 目标与首次验收范围

一次启动后，D435 发现目标电池并估计粗位置，升降把目标放进右臂舒适可达范围；D405 近距离定位，机械臂向上/向前调整到预抓姿态；最后保持夹持坐标的 Y、Z 和姿态，沿整车 +X 前伸，再闭合夹爪并检查夹持结果。

固定约定：base_link 为统一规划坐标，X 朝车头、Y 朝左、Z 向上；电池凸起朝下，带槽夹指在下，采用已约定的 J6 约 -90°抓法。J6 数字只约束关节；整个夹爪的水平姿态仍由完整六轴 FK/IK 检查。

首次运行限定：右臂、一个明确的目标电池、机器人已停在可达范围附近、目标稳定放置。底盘在首次自动抓取中保持静止，允许升降粗调和右臂运动。多个同等候选无法区分时请求选目标，不让模型任意选。完整自主导航、仓口插入和拔出锁紧电池另行建设。
升降不追求与台面齐平，也不承担最后毫米级对位；升降停稳后由机械臂和 D405 修正。目标明显侧转、不符合 +X 插入方向时提示重新摆位，首版不自动旋转底盘。

## 3. 自动流程与每一步的完成条件

1. **建立任务。** 读取右臂、升降、相机的有效反馈、标定和工具版本。获得控制所有权，防止自动任务与网页滑块/键盘同时发运动。停止/急停优先，人工接管使旧自动任务失效，不能自动续跑。
2. **D435 找目标。** 冻结彩色、对齐深度和内参；DINO/Qwen/SAM2 在这帧上产生框与掩膜。对掩膜内有效深度做稳健统计并换算 base_link 粗位置。孔内背景不能算提手表面，深度不足不能用无根据的固定距离替代。
3. **选择升降粗高度。** 在已知升降范围及右臂关节限制内寻找能伸向目标、不过度折叠、保持相机视野的姿态。先离线检查升降及双臂随动包络，包含升降带动左臂的影响。只有检查通过才粗调；到位后固定升降和底盘。
4. **D405 接管目标。** 先确认画面内同一目标。若不可见，只能执行已规划并检查过的观察姿态；不可达或无可验证路径就停止，不能盲伸。重新获取同一时刻 RGB-D、关节、升降反馈。
5. **位姿与几何互相核对。** 自动掩膜传给 FoundationPose，输出电池位姿；把 CAD 上 G/F/T 和凸起方向变换到 base_link。检查 CAD 在原图上的轮廓/关键结构是否吻合、可见模型表面与点云的距离、跨帧一致性和方向歧义。失败则有限次数重拍，仍失败就说明原因；不自动带着旧结果继续。
6. **生成预抓目标。** 根据夹持坐标到腕部的刚性变换计算腕部目标。机械臂可在这一阶段同时改变 X/Y/Z；在提手前留空距，调整到夹口中心与目标夹持处的 Y/Z 对齐、姿态水平。预抓距离是通道和误差余量参数，不是整段运动的固定示教长度。
7. **靠近后再测。** 按“移动一段—停稳—重新观察”完成有限次自动修正。每次使用新的 D405 数据和实测 FK。达到对位容差后锁定这一次的 Y/Z/姿态与最终目标；到位但视觉对位不合格仍不能闭合。
8. **执行水平前伸。** 生成 base_link 下只变 X 的夹持坐标轨迹，逐点换算腕部目标与连续 IK，检查整个路径和夹指扫掠体。执行中读取实际姿态并检查偏离/停滞；目标过期、障碍变化、反馈丢失则停止。最后近距离盲区不能虚称持续可见，进入遮挡前必须有可信的终点和净空。
9. **闭合与核验。** 终点及实际插入深度满足条件后才闭合。关节到位/夹爪闭合只是动作反馈，不代表夹住。用可获取的夹爪状态与新的视觉观测验证目标是否在夹指之间；图像遮挡、证据不足则显示“夹持未确认”。首轮不宣称完成无人机电池解锁拔出。
10. **结束和释放资源。** 保存这一轮观测、估计、指令、反馈和失败原因；关闭此次租用的深度，恢复此前设置；结束 GPU worker。失败停留在明确状态，禁止无限重试或自动回零。

## 4. 位置计算和抓取长度

所有控制目标通过矩阵计算：
T_base_camera = T_base_wrist(q, lift) × T_wrist_camera（D405）
T_base_battery = T_base_camera × T_camera_battery（FoundationPose）
T_base_grip = T_base_battery × T_battery_grip
T_base_wrist_target = T_base_grip × inverse(T_wrist_grip)

D435 使用自己的安装外参，不能直接套用 D405 手眼。
升降粗调仍需有效的升降反馈/模型；每次升降后重拍，以免用旧坐标。
当电池方向与固定 +X 抓法不兼容时，不强行把变换后的点压平为水平线。

已有 CAD 候选指尖越过提手前沿约 26 mm；它不是腕部总前进距离，也不是已验证的安全限位。
先由视觉确定目标表面与 CAD 抓取点，再由工具变换得到腕部终点：
实际待前进距离 = 本次腕部终点 X - 本次已对齐腕部起点 X。
预抓点与终点共享 Y/Z 和姿态；原位置只有已满足对位与净空条件时才能直接充当预抓点。

旧示教偏移属于特定夹指和姿态的实测数据，保留用于对照；
不能把旧夹指偏移、V2 CAD 名义 TCP 和新视觉点混用。
新的 V2 TCP/安装变换必须有版本和核验记录。CAD 只能提供名义初值。

## 5. 必须补齐的最小连接层

- **共享冻结观测。** 一个 snapshot_id 绑定 camera_id、RGB、对齐深度/单位、内参、曝光时间、同步关节/升降及标定版本。检测、分割和位姿必须引用同一份数据。当前识别流与 FP 独立拍照，直接拿最新识别框套另一帧不可行。
- **自动掩膜输入。** 给现有 FP worker 增加经过形状/大小/帧 ID 校验的 mask 输入；保留 ROI/GrabCut 作为人工诊断入口，不需要另一套模型。
- **工具变换与轨迹。** 从 CAD/已核验 TCP 导出腕部目标。现有 arm.wrist 是终点 IK 后发 arm.joints；仅修改终点 X 不保证中间路径水平。补充带速度、连续 IK 和反馈检查的笛卡尔轨迹执行，不能靠发送一串异步终点冒充轨迹控制。
- **单次任务状态机。** 在现有后端组织步骤、超时、取消、控制权和结果。几何计算/IK/运动策略由确定性代码负责，Qwen 不直接决定关节指令。
- **结果检查与页面。** 在 9983 提供一次启动、停止、当前步骤、失败原因、目标/CAD/点云/预抓路径/实际反馈。自动流程不要求每一步手动框选或抄 XYZ；保留人工选择目标和诊断入口。

GPU 策略沿用按需进程：检测/分割结果保存后释放其本地 GPU worker，再运行 FP；确认前一阶段退出后才分配下一阶段，避免 8 GB 显存同时驻留多个大模型。取消/超时必须回收子进程。
深度通过现有采集进程的租约按需获取，不另开相机管线，不重置共享 USB 主控。
无需引入通用大 Agent 框架、恢复 GraspNet 或重新训练电池模型。

## 7. 验收和仍待实测的参数

“跑通一次”的最终含义：一次启动、目标无歧义、无需手动框选/抄坐标，自动完成粗调、对位、前伸和闭合，并给出可核对的夹持证据。只输出坐标或夹爪闭合不算完成。
首次完整成功不代表已具有比赛所需可靠性；需改变位置/高度后统计成功率和失败类型。

上线前确定并记录：视觉位置/姿态稳定阈值、深度/模型残差阈值、工具对位容差、预抓余量、轨迹速度/加速度、真实到位/停滞容差、重试和超时预算、夹持核验规则。
这些值必须来自 V2 实物槽/凸起公差、定位重复性与受控测试，当前不编造通过阈值。
1.8 mm 名义槽底间隙不能直接视作可容忍的整体视觉或 Z 误差；还要考虑打印、安装、姿态和挠曲。

当前实际边界：识别、深度、点云、位姿预览与腕部控制已有；自动串联、完整碰撞/直线执行、可靠工具变换和抓后判定尚未端到端验证。下一步先实施 A，在 9983 自动显示整条链路的结果，再进入运动阶段。

### 反馈到位判据（离线模块）

`agent/motion_feedback.py` 复用控制台 snapshot 的右臂/升降反馈，使用 ROG
单调时钟 `received`，不能与相机 epoch 时间混用。`tool_feedback` 以实际关节
FK、实际升降和明确 TCP 计算误差；TCP 为空、底盘活动、升降改变或反馈不配对
均拒绝。它不读取 SDK 零位 XYZ，也不把视觉参考点直接当腕位。

`ArrivalMonitor` 要求命令之后的新样本、目标容差内、连续采样且速度低于明确
阈值，并持续停稳。重复帧不会累计停稳时间；缺帧、驱动故障、取消、超时和
无进展均返回终止状态。终止后不可自动续跑。阈值无实机默认值：测试中的数值
仅用于模拟，不写入控制配置。夹爪位置到位不等于确认持物。

底盘字段只说明当前控制台没有运动指令，不能证明车体实际静止。到位回执也不能
代替闭合前的新鲜状态复查。

本模块没有运动/停止 transport；`stop_required` 是执行器必须处理的请求，
不是已发送停车或硬件已停稳的证明。还未接入真实自动执行器或发布为 Agent
运动工具。下一阶段需用它约束插入完成与后续闭合，并保留取消后不续跑的规则。


### 插入后闭合顺序（软件验证）

`PickMonitor` 已将前述到位判据用于插入/闭合阶段：只有 TCP 位姿连续停稳才进入
`ready_to_close`；`start_closing` 还要求比到位回执更新的一组配对反馈，并复查
工具位置、完整旋转向量的变化速度和升降，才返回一次 `close_permitted`。
旧回执、重复调用、漂移、反馈失效、取消或故障不会再次许可闭合。

闭合后的反馈仍检查腕部是否保持目标，夹爪连续到位仅进入
`awaiting_hold_verification`，不会将“夹爪到位”当作“夹到电池”。TCP 缺失时
不能构造此监控器；没有将测试 TCP 写入实际配置。测试同时复用了真实 Controller
的 snapshot/夹爪协议与 FakeAdapter，未连接 SDK、CAN 或相机。

此阶段是执行器内的反馈顺序逻辑，没有网络端点或真实命令线程。后续绑定必须在
同一控制所有权锁内完成闭合前复查和下发；命令失败/回执未知须 abort，不能重发。
还需环境扫掠验证、受限时序、控制所有权及独立抓后验证，当前仍不能实机自动抓取。


### 同一控制台的任务控制权（未部署）

Controller 新增进程内任务令牌，以 command_epoch 核对申请时的指令状态。
持有期间其他网页、手眼采集的普通指令统一拒绝；腕部 IK 解算前后都检查，
避免解算期间取得控制权后仍下发旧网页目标。令牌不进入 HTTP 或 snapshot。
人工停止仍允许，并使旧任务令牌永久中断；停止请求失败也不会恢复旧任务。
任务结束释放后旧令牌仍不能下发，重新任务需新令牌。snapshot 只公开占用与
中断状态。底盘停止允许另一网页抢停，不再被原底盘网页占用挡住。

此锁只覆盖当前 Controller，不能阻止其他 ROS 节点/独立 SDK 进程直接发送。
取得控制权不等于实机静止；停止一个部分也不等于停止其他部分。后续执行器
必须响应中断、停止其参与运动的部分并核验，再释放控制权；目前没有启动
自动线程或改变现有驱动。


### 到位监控与夹爪下发连接（未部署）

`agent/pick_execution.py` 的 `PickCloseStep` 复用现有 Controller：插入的实际
TCP 反馈连续停稳后，还要在同一控制锁内取得更新反馈并再次检查，才下发一次
夹爪目标。预检仅接受进程内有效任务令牌，不接受网页客户或其他命令种类。
驱动确认等待位于控制锁之外，反馈和人工停止仍能进入；确认期间出现人工停止

### 插入路径时间参数化（未部署）

`plan_insert(..., timing_limits=...)` 可为已通过连续 IK/立柱检查的插入路径
生成 `timing`，使用每段共享的五次标量插值，六轴同步，每个节点速度和加速度
均为零。它不改变已检查的关节空间曲线；保持原有 TCP 位置偏差和姿态检查。
每段时长根据显式六轴速度/加速度、TCP 速度/加速度限制计算。TCP 界使用
机械臂最大半径加工具长度的保守解析界，而不是只检查稀疏时刻。

没有默认实机加速度或 TCP 速度；测试数值只用于离线验证。关节速度不得超过
当前 X5 驱动的 5.7 deg/s 上限。TCP 为空仍返回 tcp_pending，不输出腕部轨迹。
未提供 timing_limits 时保留已有纯几何预览。接近预抓点的关节空间段不包含
在这份插入时序中，需要单独检查和安排。

`TimedJointPath.sample` 返回指定轨迹时刻的关节位置、速度和加速度，拒绝
非有限、负数和超出总时长的采样。当前驱动尚未消费这一协议；不能将它转成
一串异步 arm.joints 指令冒充有时序的执行。尚需驱动内执行、实际跟踪监测、
环境/夹指扫掠验证、现场参数核验和受控实测，全部结果 executable=false。
本阶段未修改或重启机器人驱动，未部署网页。
