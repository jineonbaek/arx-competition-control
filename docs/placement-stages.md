# 放置页三个独立步骤与 Z 控制

页面：`http://192.168.3.45:9983/visual-docking.html`。新控制区不自动串联，
底盘、升降、左臂保持，不自动松爪和返回；原完整放置/比赛流程保留。

1. 预观测：记录当前点，或编辑夹持 TCP XYZ/朝向、六关节点后保存；只保存
   不运动。执行按钮才移动到保存的右臂关节点，升降使用当前读数。
2. D405：显式开启实时观测，不运动；默认仅修 Z，可选 Y 或 Y+Z。执行修正
   才进行新的 RGB-D 采集与右臂微调。没有修正次数/总超时上限；实测不移动
   或新画面的误差不改善时保持，避免持续发无效目标。被遮挡的边线不补造。
3. 入仓：从当前位置单独执行，默认 160 mm、8 mm/s，范围 1–200 mm、
   1–30 mm/s。选视觉高度时读取实际仓口轴并保持仓口坐标中的 Z；选模型
   时沿 +X 保持机器人 Z。仅表示测得的推进行程，不宣称到底或自动松爪。

仓口中心默认 630 mm，**用户暂定值**，可以在页面修改并取消暂定标记。
实时卡片分别显示仓口参照高度、模型高度（含实际升降读数）、相对仓口高低。
仓口参照 Z 的计算为：

`630 + dot(仓口竖直方向_机器人坐标, 当前TCP位置 - 实测仓口高度中点) × 1000`

从红框实际相对内沿和深度平面恢复竖直方向。因此同帧相对几何能抵消共同的
底盘高低/倾斜等误差；显示的综合 Z 修正不能单独当成底盘测量值。仓口视作
固定竖直物体，标定及深度误差仍存在，不宣称已经实机测量到指定精度。

视觉参考超过 2 秒、底盘输出代次改变、驱动改变或缺少真实相对内沿时，
仓口参照高度显示不可用，不以模型值冒充真实离地高度。可用已知当前 TCP
高度做手动偏置标定，或明确切换到“机器人模型（未补偿底盘误差）”操作。
手动偏置不测量倾斜；底盘移动后失效。

参数保存在车载 `web/hardware/runtime/placement-stages/settings.json`。
每阶段记录在 `reports/placement-stage-*/receipt.json`，含计划、实际、累计
用时、初末位姿和原生轨迹接续信息；每轮 D405 保存对应画面和深度几何结果。
读取/编辑/保存不发运动，阶段需显式按钮启动。页面加载只有 GET。

rclpy；2 项 handeye_steps 的 Fake.lock 测试桩错误）。全量 Node 49/50，原有
chassis-session 稳定控制 ID 测试因 ChassisOutput 未注入测试环境报错，相关
main.js 和测试文件均与 HEAD 相同。未做机械臂运动验收、未推送 Git。
