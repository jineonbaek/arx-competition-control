当前承载轨迹修复
================

现象：2026-11-20 当前位姿 +X 自动推入启动后，腕部 Z 由 531.19 mm
降至约 528.65 mm，原位姿保持参考被新轨迹的实测位置替换。

修复范围：驱动公开已发送关节参考与夹爪目标；轨迹第一点绑定该参考；
执行器将整段关节曲线作常量平移，保留已有承载偏置，已补偿的曲线不重复叠加。
常量平移不改变关节速度、加速度和时间表；执行前重新检查限位与臂部路径。
已有 2 度补偿界限、反馈停止和夹爪保持语义保留。
底层同样锚定旧调用方的名义曲线，避免未经过 DockingMotion 的抓取轨迹回到
实测起点；已补偿曲线的底层附加平移为零。底层再次检查所有平移后的限位。

负载配置：SDK 的 link6 质量由原来的 0.650 kg 增为 0.800 kg，即附加
0.150 kg 电池。电池真实重心未测量，本补丁不编造重心或改变惯量、增益。
这项修复验证的是轨迹衔接，不是重心标定或实机入仓验证。

实施顺序：先回归复现；再修复、纯软件回归、独立目录编译；备份源文件与
旧二进制。运行中的 SDK 驱动退出会切到阻尼，所以电池仍被夹持时不热重启。
待现场确认电池取下或有可靠外部支撑后，只切换右臂驱动，不启动运动示例。

SDK 启动回零修复
----------------

首次切换后现场确认实际回零。厂家共享库 ControllerBase::Init 在返回前强制
运行 stateGoHome 约 3550 ms，并对夹爪发送重新置零；在构造之后设置阻尼
来不及阻止。原厂家库 SHA-256 为
d07d53d14da17f0a1db2753e3339f9e4c055dad72df613c811b9692c4bede85c。

prepare_no_home_sdk.py 仅接受该精确文件，为右臂生成独立共享库副本；将
Init 的模式写入由 1 改为 2，在完成初始位置读取后跳转到原函数的正常清理，
跳过回零及夹爪置零。两个指令区以外的所有字节保持一致；保留通信、错误
清理、使能、反馈与阻尼初始化。原厂家库和正在运行的左臂不替换。
右臂启动脚本验证副本；驱动在创建 CAN/SDK 对象前确认实际加载路径，
缺少该副本时拒绝启动，避免静默回退到强制回零的厂家库。

验证：8 个承载/执行专项 Python 测试、2 个共享库文件测试通过；C++ 轨迹
与关节限位测试通过。未加载修正版库的右臂驱动在 CAN/SDK 构造前退出，
未创建 SocketCAN。全量网页回归的现有错误名称与原版本相同：221 项缺失
rclpy，以及 test_handeye_steps 中两个 Fake.lock 测试桩错误。完整日志保存在
车载 reports/loaded-reference-fix-20261120-230529；不把这些检查称为实机入仓通过。

启用结果
--------

右臂运行进程 1508481，反馈 ready=true、startup_no_home_sdk=true、status=idle，
夹爪目标为 0。第二次切换的最大关节变化约 1.01 度；SDK 初始化由原约
3.6 秒降为约 42 毫秒。该检查在首次已回零的位置进行，不等同于离零位带载
启动验证。左臂进程 4431、机体进程 4825 均未重启。

第二次切换前有电池、切换后为空爪，现场已确认由操作者取下或接住；因此
夹持反馈变化不作为保持载荷通过证据。未执行新推入或回到旧参考点动作。
首次 SDK 自动回零确实改变了实物姿态，旧标定文件保留，下一次放置需重新
到达预观察点并观察。负载质量仍为 150 g；真实电池重心仍未单独标定。

全量回归为 553 项，223 项错误与原版本 547 项测试中的错误名称完全相同，
无新增错误。另两个非依赖错误是：
test_handeye_steps.WorkflowTests.test_only_owner_click_can_consume_one_ticket、
test_handeye_steps.WorkflowTests.test_probe_failure_releases_depth_without_motion，
均因旧测试桩 Fake 缺少 lock。其余 221 项因当前离线环境缺少 rclpy。
