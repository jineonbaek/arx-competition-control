# PLAN F 两份结果保存与两级兜底重试方案

日期：2026-11-21。

状态：方案稿，尚未实施、部署或重载。本方案不接入 Codex 接管。

## 1. 目标与范围

正常 PLAN F 保持原样。在预夹取位重新观察或后续精纠过程中，视觉结果失败并按原有重试逻辑仍无法继续时，使用本轮已经保存的有效目标重新规划，避免仅因后续视觉不可用就结束整轮抓取。

本方案的工作假设：避障位首次观察后，电池和底盘保持不动；右臂和 D405 可以移动。

只涉及三项新增衔接：

1. 保存避障位结果 A 和预夹取位结果 B。
2. 在原视觉失败出口前，按 B → A 的优先级切换目标来源。
3. 兜底重新规划总共最多尝试 3 次。

不新增位置、姿态、深度、置信度、时间或运动到达的验收门槛。正常识别顺序、现有视觉重试次数和精纠循环保持原逻辑。

## 2. 位置定义

| 名称 | 含义 |
|---|---|
| 避障位 | 开始比赛后右臂已到的避障预设位，D405 在这里首次识别和计算抓取目标 |
| 预夹取位 | 最终夹取点 T 前方 50 mm，D405 在这里进行首次复查 |
| 精纠过程 | 预夹取区域内的小步修正及移动后的复拍，不是第三个固定点位 |

本文中的预夹取位也是此前讨论中所称的“预观察位”；不恢复已经取消的固定 700 mm 观察动作。

## 3. 保存两份结果

### A：避障位结果

首次识别、CAD 位姿和抓取几何通过原有检查，已经形成可用于正常预夹取规划的完整结果时，保存 A。

### B：预夹取位结果

第一次到达预夹取位，重新观察得到通过原有检查的完整抓取目标后，保存 B。即使随后还需要精纠，也可以保存该有效目标。

若这一位置的识别、深度、CAD 位姿或凸台方向等既有检查未通过，就不产生 B，继续保留 A。

### 保存内容与方式

在本轮现有 `state.json` 中保存两份独立拷贝，复用已有观测和计划文件：

- 机器人坐标系下的完整电池位姿。
- 夹指尖 TCP 最终目标 T。
- 对应预夹取点、夹取姿态和插入方向。
- 原观测编号、预览和计划文件引用。
- 原有 CAD、手眼、TCP 与配置绑定信息。

保存目标几何及其证据，不把当时的旧关节轨迹作为后续重试轨迹直接播放。失败的新结果不覆盖 A/B。

如果连 A 都没有生成，说明没有本轮可用的有效目标，本轮仍走原有失败处理。

## 4. 正常主链路

```text
避障位首次识别、位姿计算、正常规划
    ↓
保存 A
    ↓
按原逻辑张爪、移动到预夹取位
    ↓
预夹取位重新观察与计算
    ├─ 得到有效完整结果 → 保存 B → 原有精纠循环
    └─ 视觉失败且原重试用尽 → 兜底入口

原有精纠循环
    ├─ 达标 → 原有插入抓取流程
    └─ 后续视觉失败且原重试用尽 → 兜底入口
```

正常流程未失败时，不触发兜底，不多拍图、不多发动作。

## 5. 哪些失败进入兜底

仅在预夹取位首次复查及后续精纠相关的视觉处理、目标计算阶段衔接：

| 情况 | 处理 |
|---|---|
| 找不到目标、跟踪失败、掩膜识别不通过 | 先走原有识别重试；仍失败则进入兜底 |
| 有效深度不足、深度范围异常 | 先走原有视觉重试；仍失败则进入兜底 |
| CAD 位姿与深度匹配未通过 | 先走原有位姿恢复、重拍逻辑；仍失败则进入兜底 |
| 后续视觉估计使凸台方向等几何检查不通过 | 丢弃该次失败结果，进入兜底，缓存目标仍须按原检查重新规划 |
| 视觉预览发生 OpenCV 绘图等异常 | 若 A/B 已存在且未下发新的运动，则使用缓存目标重新规划 |

在原本调用整轮失败结束、释放控制权之前接入，不等待整轮退出后重新启动任务。

以下情况继续走原有停止和恢复处理：人工停止、控制权失效、驱动异常、机器人反馈无效，以及已经下发运动后出现的执行失败或未知回执。兜底不能自动重发状态不明的运动。

## 6. 两级优先级与“三次”的定义

**本稿将“三次”定义为：本轮缓存兜底重新规划总共最多 3 次，包含第 1 次。**不是每一级各 3 次，也不是反复下发 3 次抓取动作。

顺序：

1. 有 B 时优先尝试 B。
2. B 没有生成，或者用 B 重新规划不通过时，转 A。
3. 剩余次数使用 A，每次重新读取实际关节和升降反馈。
4. 3 次都未形成通过原检查的可执行路线，进入原有失败出口。

| 缓存情况 | 最多三次的来源顺序 |
|---|---|
| A、B 都有 | B → A → A |
| 只有 A | A → A → A |
| A、B 都没有 | 无可重试目标，原有失败处理 |

选择这一顺序是为了在较新结果不能继续规划后，使用更早已经支持正常接近动作的 A。若实际起姿与输入没有变化，重复规划未必能产生不同结果；三次尝试不保证一定有解。

此处的 3 次只用于兜底循环，不修改原有视觉重拍次数和正常精纠轮数。

## 7. 每次兜底具体执行什么

1. 取出本次采用的 B 或 A，固定其 T、姿态和插入方向。
2. 读取当前右臂实际关节、升降反馈。
3. 用已有的接近与插入规划代码，重新生成当前位置到该目标的剩余路线。
4. 按原逻辑执行 IK、关节限制、轨迹时序和路径检查。
5. 规划未通过、尚未下发运动时，进入下一次兜底规划尝试。
6. 规划通过后，将新计划交给原有插入抓取执行器，不再回到本次失败的视觉精纠环节。
7. 后续运动失败时，沿用原有停止处理；不因有剩余规划次数而换一个缓存重发运动。

计划来源需要明确记录为“使用本轮缓存目标”。不把旧观测改名为新观测，不伪造 `aligned`，不把兜底冒充已有的其他快抓模式。

## 8. 兜底后接回原流程

```text
缓存目标的新路线通过原检查
    ↓
原有 execute_pick
    ↓
到 T，夹爪闭合目标 0
    ↓
原有夹持确认
    ↓
原有底盘撤出
    ↓
原有右臂运输动作
    ↓
原有比赛阶段完成与导航交接
```

不额外返回避障位，不重新执行整轮抓取，不重复已完成的撤出或运输动作。接近目标所需的轨迹由原规划函数计算。

升降、左臂、夹爪、底盘撤出、运输姿态和比赛交接继续使用实施时的现有配置及实现。

## 9. 最小代码落点

| 位置 | 需要处理的内容 |
|---|---|
| `agent/battery_flow.py` | 在成功节点保存 A/B；在原视觉失败出口前衔接兜底；记录最多 3 次的规划尝试 |
| `agent/battery_tools.py` | 读取缓存目标、绑定原证据与新计划，正常流程继续使用原入口 |
| `agent/battery_pick_plan.py` | 复用现有规划函数，以当前反馈作为起点，以缓存几何作为目标 |
| `agent/battery_execution.py` 等现有计划来源处理点 | 接通明确的缓存来源计划，复用已有单次接近、插入和闭爪执行核心 |

实施时需要调整的是缓存目标与执行入口的来源衔接。不能将旧观测编号直接塞给“必须使用最新观察”的原调用，也不能全局关闭观测和标定绑定检查。

本方案不要求修改识别提示词、参考图、DINO、SAM2、FoundationPose、Qwen 的选择策略或数学算法。

## 10. 日志

复用现有任务事件和执行回执，至少记录：

- A、B 的保存位置及原观测编号。
- 原视觉失败阶段和失败原因。
- 当前为兜底第几次，采用 A 还是 B。
- 当前反馈所生成的新计划编号及规划结果。
- 进入正常插入，或三次耗尽后退出。

日志示例：

```text
预夹取位位姿核验失败，原视觉重试已用尽
缓存兜底 1/3：采用预夹取位结果 B，原观测 obs_...
B 重新规划未通过，尚未发送运动
缓存兜底 2/3：采用避障位结果 A，原观测 obs_...
A 重新规划通过，新计划 pick_...
进入原有插入抓取流程
```

## 11. 验证项目

- 预夹取位首次视觉失败、没有 B 时，可以使用 A。
- 保存 B 后精纠视觉失败，优先使用 B。
- B 规划失败后转 A；总共不超过 3 次缓存规划尝试。
- 新规划使用当前实际反馈，缓存目标和原始观测文件保持不变。
- 没有可用缓存或三次都失败时，保留原失败原因并退出。
- 正常视觉成功时，原流程及其动作顺序不变。
- 已下发运动出现未知回执时，不调用下一份缓存重发动作。
- 不修改任何既有容差和验收数值。

本次只形成方案文档。缓存兜底仍会继承 A/B 最初的目标选择和定位误差；它不能纠正首次误选机器人夹爪的问题。
