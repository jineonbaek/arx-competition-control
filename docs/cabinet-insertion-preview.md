# 红色矩形仓口：固定Z水平入仓预览

用户已明确：演示用第二个STL；比赛为大电池仓上排中间；一个目标窗口可横向放两块电池，先选左半；仓外允许先对齐高度，入仓段保持Z不变。本功能没有运动、控制权申请或夹爪执行接口，旧地面下降放置保持禁用。

## 实测与模型

- D435当前样本可完整看到红色矩形仓口；D405左边框超出画面，报告partial，不补齐隐藏角点。
- 两模型的净口均为169.6×79mm。大仓模型前面为Y=0，目标upper_2；演示模型前面为Z=304。模型自身轴不同，不能直接套同一变换。
- 从STL前沿面边界提取开口轮廓，忽略微小纹理孔。沿目标左半中心射线首次命中内部模型表面约150.1mm；这不是以外观总深度替代实际通行深度。
- 电池完整投影横截面约82.35×75mm，带真实圆角。两块电池并排总横向余量仅4.9mm。左半理想静态净距约1.2mm，不能沿用抓取18mm或地面放置30mm容差。
- 电池STL包围盒中心与原抓取参考T的横向差约5.031mm，TCP路径已按完整参考点偏移换算，不能把电池中心直接当TCP。

## 识别和规划

1. 通过既有唯一相机拥有者申请配对RGB-D，沿用本轮反馈与相机外参；采集结束归还深度租约。
2. 检测闭合红色矩形内框并拟合直边。以前沿红色边框有效点拟合3D平面，禁用孔内背景深度作为仓口位置。
3. 角点射线由工厂去投影后的XYZ局部插值得到，和前沿面求交；核对模型与实测尺寸。取两者保守内包络，实测过小即拒绝。
4. 选择左半区。保持入仓轴的世界Z分量为0，保持工具旋转不变。先在仓外对齐预插入TCP，再沿水平线到终点。
5. 检查电池真实投影包络在入口与最深处均位于开口内；后壁余量10mm覆盖全部截面点。路径不默认反向套200mm。
6. 由电池前端位置换算原抓取定义的TCP参考T，复用plan_insert计算腕位/IK/原立柱检查。这只是计算，不调用Controller.submit或start_trajectory。
7. 图上青色为实测内框，蓝色为TCP路径，绿色为电池前端路径。仓外高度对齐与固定Z入仓分开显示。失败/新模型/新相机结果清除旧路径，不混合不同冻结帧。

在该模型的保守深度下，电池前端约进入140mm，长度约195.28mm，预计外露约55mm。表面残差、外参/持物关系及末端误差必须小于净距后才能讨论执行；目前所有结果executable=false。完整夹爪、左右臂、桌面、线缆和现场碰撞未验收。

## 来源

config/cabinet-profiles.json记录两个输入STL的SHA-256、开口轮廓、坐标轴及模型射线结果。config/battery-envelope.json记录与原抓取模型一致的电池哈希和投影。原始STL只在独立目录vision/models/cabinet保留，不上传Git。

当前接口：GET/POST /api/cabinet-preview，仅允许camera与model。页面 /placement.html 为只读识别/水平路线预览，不提供旧下降放置或实机启动操作。未推送代码；实机运动次数为0。

数值逆解会尝试有限个初值，但候选解必须重新检查从真实起始关节到目标的CAD扫掠，不能用求解初值冒充实际起姿。当前升降高度无解时，只读比较10/8/5.52rad的仓外高度条件；显示候选高度及双臂升降沿途尚未检查，绝不下发升降指令。

开口净距采用CAD与实测尺寸的保守包络；实测开口小于电池时拒绝规划。二维识别成功但深度不足仍保留真实内框，路径为空。当前选中的相机决定路径详情，其他相机旧结果不得覆盖，新失败结果清除旧路径。
