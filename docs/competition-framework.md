# 整场比赛框架（第一版）

入口：9983 `/map.html`。目标固定为无人机指定左上角电池，放入充电柜红框 A 口，无口令解析。

顺序：`navigate_pick → pick → carry → navigate_place → place`。`place` 的完成结果应覆盖插入、释放、撤指、稳定至少 3 秒。导航任务的完成结果必须代表到工作区且已停稳。

当前注册 `navigate_pick`、`pick`、`carry`、`navigate_place`。导航复用同事已准备的路线及9985交接协议；抓取直接复用原工作流、配置和容差。最新抓取末端已经包含返回运输关节位，`carry`只读取同一抓取运行的`carry_ready`真实回执，不追加运动。`place`尚未接入，到柜前停止清理，不伪造放置或整场成功。模拟任务仅存在于隔离测试。

## 导航接入（2026-11-15）

先由导航同学启动导航执行端、在RViz准备或载入待开始路线，任务点依次为地点1（取物）、地点2（放置）；普通途经点、特殊点、路线规划和障碍处理仍由导航原实现负责。打开map.html和GET查询不会登记worker或发运动。点击开始后，总控使用导航原`TaskClient`登记并按返回的租约保活，通过自己的domain192地图观察服务发布已有`/pb/waypoints/start`，不修改navigation目录。

地点1真实到点停稳后，取得作业运动令牌再发送accept，调用原抓取。确认原抓取和运输回执后释放作业令牌，发送complete，等待导航原线程核验并继续到地点2。地点2匹配本轮mission/visit/路线身份后才进入放置。未知/取消回执不重放原路线；通信响应不明时使用相同事件UUID和内容重试，HTTP成功不等于实际交接完成。

总控停止或无法恢复失败时，保持原夹爪状态并清理当前作业，发布已有`/pb/waypoints/clear`，确认路线取消后归还手动。停止未确认则显示“控制权待清理”，可重试停止；不会放行未确认运动。页面新增路线进度、驱动状态和交接等待原因。导航独立运行、不经过总控时，原9983本机SDK入口和RViz功能保持原行为。

路线发布由我们自己的地图观察服务承担：`navigation-command.json`/`navigation-command-result.json`只作为服务进程与domain192观察进程间的内部交接。观察进程重启忽略已存在的待发命令，不重放start；观察服务缺失、路线被修改或已有路线运行时不擅自接管。

本次未修改抓取页单次参数的保存方式：总控仍调用原`start_owned()`读取原模块`task_settings`。页面单次输入尚不自动成为共享默认值，后续若统一保存，应在原抓取模块解决，不另建map参数或修改现有动作/容差。

## 模块接口

在服务端构建时调用 `competition_task.register(stage, module)`。这是 Python 内部注册，不预定雷达同事的 ROS/HTTP 消息格式，也不修改导航代码。

模块实现以下四个方法：

- `start(context)`：同一 `request_id` 只能启动一次。先检查 `context['cancelled']`；发动作前再次检查。返回 `status` 为 `accepted`、`running`、`completed`、`failed`、`stopped` 或 `unknown` 的字典。
- `inspect(context)`：读取同一任务的真实状态和回执，不发送运动。不能将旧回执误作当前动作的完成。继续前应检查当前位置、持物、工作区等本任务所需条件；信息不足返回 `unknown`。
- `stop(context)`：幂等停止本任务，保持夹持，不回零、不下电；完成清理后返回 `{'stopped': True}`。不得在返回后又发送运动。停不下来返回未确认，控制权不虚报已释放，网页允许重试停止。
- `resume(context)`：仅在 `inspect` 返回 `{'status': 'stopped', 'can_resume': True}` 时调用。沿原目标完成剩余部分，不能重跑已完成动作；没有恢复能力不能声明 `can_resume`。

`context`包含`run_id`、`stage`、稳定的`request_id`、进程内作业`token`、整场`competition_token`、`cancelled`线程事件、`controller`和`environment_clear`。令牌不通过网页或日志序列化。作业令牌由总控在阶段间获取/释放；子任务不能擅自释放。导航阶段无作业令牌，以满足原导航协议的`motion_reserved=false`要求；整场令牌仍在后端阻止手动和另起自动任务，只有原本机导航通道在获准阶段可以运动。停止入口始终保留。

雷达同事负责路线和导航内部实现；我们的适配将已有到点协议转换成上述任务状态，同一通知须匹配本轮mission/visit及工作区。导航具体恢复动作仍留接口，不把取消后的旧路线从头启动冒充继续。

## 异常与继续

正常顺序不调用 Qwen。模块内部已有的识别重试、视觉纠偏、导航重规划保持原逻辑。

异常时，总控向 Qwen 提供当前阶段、原任务状态、完成记录和机器人反馈。Qwen 通过已有 `QwenClient` 只选择已注册恢复任务；判断不明确、没有能力、模型调用失败均停止推进并清理控制权。模型调用本身不执行动作；停止后迟到的模型答复被丢弃。

具体恢复动作先不实现。模块可以通过 `recoveries = {'名称': recovery_module}` 注册恢复任务，接口同上。恢复完成后必须再次读取原任务状态，不能单凭模型声称成功推进流程。

停止后保留完成记录。“检查并继续”重新获取控制权、读取当前反馈并核对中断任务：已完成则进入下一任务；仍在执行只查询原回执；明确可恢复才调用 `resume`；否则进入异常分析。完成动作不重新 `start`。抓取中断阶段的具体恢复尚未接入，不伪造继续能力。

整场运行及异常恢复期间总控保有控制权；整场完成、主动停止或无法恢复失败后交还 9983。实际停止未确认时显示“控制权待清理”，不能假称手动已经可用。

任务日志位于 `agent/competition-runs/`，不提交运行记录。第一版不做跨服务重载/重启恢复，不自动恢复运动；重载后是新的待机总控。

HTTP：`GET /api/competition-task` 查询；`POST /api/competition-task` 的 `action` 为 `start`、`stop`、`continue`，均带 `request_id`。开始/继续还携带当前 `expected_epoch` 和沿用已有的 `environment_clear=true`。身份和 Origin 检查复用现有控制台；重复请求不重复启动。

导航接入完成隔离协议、控制权轮转及页面验证；未启动真实路线或抓取。原抓取已有运输回执不代表整车载物过障实车验收，放置尚未注册。
