# 电池入仓链路：离线完善记录

本轮范围：代码检查、离线回放、自动测试。没有采集新实机画面、发送运动/夹爪指令、切换在线程序、重启驱动或推送 Git。保存的实拍数据只作历史回放。

## 当前链路

已有彩色帧及对应关节/机体反馈 → 相机身份与时间配对 → 唯一完整红框 → CAD净口平面PnP → 相机到基座变换 → 原抓取TCP → 左半区模型包络 → 仓外对齐预览 → 固定世界Z入仓几何 → 状态与来源绑定 → 网页预览。

D435 是主定位源。D405 只提供辅助结果，红框不完整不清除、不替代 D435 目标。仓口取图不再申请深度模式，也不使用点云碰撞计数。旧深度算法仍保留供原调用者使用。

RGB定位检查画面尺寸、焦距、序列号、畸变模型、反馈配对、完整红框、正深度与重投影；保留平面PnP候选和歧义标记。彩色红框内缘必须对应CAD净口，这一尺寸与贴标偏差仍是未实测的假设。像素重投影误差不能代表毫米定位精度。

原TCP文件 `config/right-grip-tcp.json` 继续使用，SHA-256 为 `0c6dcdb08f51b671343a19ecf5e5c62c973b021ef7769385765dfe5b8b9689b6`。D435 外参状态仍为 `nominal CAD preview; physical accuracy not measured`。沿用TCP不等于已验证相机到基座的精度。

冻结结果最多保留30秒的“当前预览”资格。机器人运动、指令序号、关节、升降、夹持、机体姿态、反馈时效、TCP、模型、标定或规划源码变化后，GET结果清除路径和三维坐标，仅保留带过期状态的历史图像。失效结果不会再次自动恢复。网页断线、切换模型和迟到响应也清除旧目标；D405采样期间继续检查D435结果时效。

所有结果均为 `executable=false`、`readiness.execution_ready=false`。本轮没有增加负载执行器、松爪逻辑或执行许可。现有空载演练接口仍按原规则工作，不能拿来执行带电池入仓。

## 无硬件离线回放

在独立目录中，使用已安装NumPy/OpenCV的Python：

```bash
python scripts/replay_cabinet.py /path/to/saved-frame.npz --model demo --output reports/cabinet-replay
```

输出 `result.json` 和 `preview.jpg`。脚本没有连接机器人或相机的接口，不导入ROS控制器；只加载保存的帧。它按历史曝光时刻验证帧内配对，另行报告实际帧龄，强制将当前有效性与执行许可设为false。缺少机器人模型时，关节路径明确显示不可用，不冒称已通过整机路径检查。

真实D435历史帧的本地回放产物：`reports/cabinet-offline-real/`。本次能识别红框并生成左半区固定Z几何，`z_range_mm=0`。图中的蓝线是TCP模型路径，绿色是电池前端路径；不是已经执行的轨迹。
