# 自动放置：一个红圈的左侧

工作树：`/home/arx/arx-place-integration`，分支`codex/automatic-placement`，基于当前主线ec911f6。
界面源码为 `/placement.html`，与自动抓取使用相同样式、相机卡片、分阶段日志、启动与停止机制。
本次仅编写、检查和离线测试，未启动此网页服务、相机、CAN、驱动或运动，未向GitHub推送，也未修改原工程。

## 行为

1. 核对本机最新抓取任务确实完成、夹持反馈仍在原策略范围；不跳过更新的失败抓取。
2. D435配对深度中检测唯一红色闭环，拟合实际支撑面和米制圆形。
3. 以机器人正对区域时左侧（base_link +Y在支撑面投影）选择圈内左落点，检查两块电池的空间、完整底面、边缘余量和左侧占位。
4. 右臂保持夹持、升降保持当前位置，按现有五次时序轨迹到预放位置（底面高于支撑面80mm）。已有抓取升降设置不会在持物阶段重用。
5. D405重新定位同一红圈与支撑面，修正预放位置，再获取动作后新帧。目标不一致时停止，不追随突变位置。
6. 检查IK、原CAD立柱路径及电池包围盒对支撑面的扫掠。下降速度上限5mm/s，预放/撤回10mm/s，且不超过原策略限制；不修改电机增益或原抓取参数。
7. 实测姿态稳定到位，电池底面四角高度均在3mm以内，才能发一次松爪；使用新的夹爪反馈确认张开。
8. 撤回80mm。新D435画面复用原电池识别/分割流程，检查电池在左侧且多帧跨至少3秒位置稳定；夹爪张开本身不算放置成功。

## 容差

水平每轴最大30mm、朝向最大8°，相对抓取18mm/5°放宽。根据实际圈边界、两块电池间隔与底面尺寸自动收紧，不保证所有圈都允许30mm。
支撑高度仍为3mm。圈形、深度、平面、控制权、升降、左臂、持物及反馈检查不放宽。

## 配置与部署边界

`config/placement.example.json` 默认 `execution_enabled=false`、`placement_geometry_verified=false`。
未给 `--placement-policy` 时只提供手动红圈预览；网页打开只发GET，不开启深度、不识别、不执行动作。
只有手动点击识别或显式开始任务后才向已有相机拥有者申请配对深度，不启动第二个采集/SDK实例。
真实部署需复用原抓取策略文件、CAD、电池模型及现有手眼；示例中的 `/home/arx/arx-competition-control/config/battery-execution.json` 已只读核对存在；这不代表已部署。
新工作树未复制原始模型/下载依赖，部署前需要核对这些本机资源路径及单一相机/控制服务归属；不能同时运行两套机器人驱动。

持物刚性关系根据最近完成抓取的FoundationPose及计划插入终点推导，而非新增实测。抓取到位误差、握持滑移和TCP/外参误差都可能影响真实放置高度；开启执行前须现场核验此关系与3mm高度判据，不能仅凭软件测试开启。
没有力/接触传感器证明物理接触；支撑判据为配对深度、CAD和实测机器人姿态。扫掠覆盖原立柱与支撑面，不冒充完整场景/两臂/线缆碰撞验证；现场清空通路仍是必要条件。

## 核心文件

- `agent/placement_geometry.py`：RGB-D、红圈、支撑面、左侧底面与容差。
- `agent/placement_flow.py`：确定阶段、持久记录、取消、未知回执不重放。
- `agent/placement_backend.py`：复用Controller轨迹/夹爪接口及原抓取持物证据。
- `web/src/placement_preview.py`：唯一相机采集链复用、红圈叠加、放置后识别。
- `web/src/placement_task.py`：复用BatteryTask的控制权、线程、日志与清理。

验证见 `docs/automatic-placement-verification.md`。没有完成实机放置验收。

## 独立检查后的补强

- 到位复用原 `ArrivalMonitor` / `tool_feedback` 的实测速度、反馈接收时间、连续性及静止判据。宽容差不会放宽静止速度；松爪前再采集支撑面，再建立静止窗口，并在发送锁内复查。
- 每次轨迹发送前要求新鲜冻结证据；轨迹受显式最长120秒观测有效期限制。松爪前必须取得新的、匹配的红圈/支撑面，模型外新增障碍会拒绝松爪。
- 占位和支撑覆盖包含全部允许平移与±8°旋转的包络，不只检查名义底面。绿框按周界顺序绘制。
- 放置后的电池识别完成后，另取至少4个新配对深度帧，实际图像时间跨度至少3秒、相邻不超过2秒；模型推理耗时不算稳定时间。
- 一旦发生物理阶段，未知回执、取消或失败会留下恢复锁。新进程也扫描旧 `agent/placement-runs/run-*/state.json`；不能另起任务绕过。

人工恢复后由现场维护者在 `agent/placement-runs/recovery.json` 记录 `resolved` 字典，每个已恢复run_id对应原 `state.json` 的SHA-256、`platform_stopped=true`、`holding_state_checked=true`、`environment_clear=true`及非空`note`。该记录仅供真实停稳、已核实持物状态并排除故障后确认恢复；不是启动开关，网页不提供自动清除未知物理状态的接口，状态文件变化后旧确认失效。
