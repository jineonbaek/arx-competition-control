# 三路彩色实时预览

控制台首页新增 RealSense D435、RealSense D405、Astra Pro 三路画面。
每路图像为 640×480；原始彩色预览最多约 5 帧/秒，电池框与孔洞联合标注约 2 帧/秒。D435 另外读取深度用于有效表面测量，网页不显示深度图。
暂停显示只暂停当前页面请求，不会停止相机采集或机器人驱动。
页面隐藏时停止取帧；超过 3 秒未更新则隐藏旧图，显示离线。

## 启动与停止

从独立目录运行 `bash web/start-cameras.sh`，使用系统 Python 与已安装的 OpenCV。
相机已接入桌面“ARX 一键启动与自检”，启动时检查三路画面，自检窗口增加“相机”一项。它仍是独立相机进程，未配置开机自启。
仅恢复相机可运行 `python3 scripts/start-console.py --cameras-only`；该入口不启动机械臂、升降或 CAN。
一键启动的采集日志位于 `web/hardware/runtime/launcher-cameras.log`，相机 PID 记录在同目录 `cameras.pid`。
重复启动会复用现有采集进程；设备缺失、画面过期会在自检中列出对应型号。
停止时只向本次相机进程发送 SIGTERM，退出会释放摄像头；不要停止机器人进程来管理视频。
进程锁 `web/logs/camera-preview.lock` 防止重复采集。

通过 USB 产品名称、接口和视频节点 index 匹配彩色节点，不依赖固定 `/dev/videoN` 编号。
同型号匹配不唯一或设备被其他程序占用时显示离线，不关闭其他程序。
原始画面仅保留最新一帧，位于忽略 Git 的 `web/public/camera-live/`。
现有网页服务按静态 GET 提供这些文件，无新增端口；相机预览范围继承控制台的局域网可访问范围。

## 控制边界与验证

相机采集程序不导入 ROS、机器人 SDK 或 CAN 接口，网页相机模块只发送 GET 请求。
接入过程不重启现有网页服务，不修改 `control.py`、`ros_adapter.py` 或控制配置。
验证包含原子写帧、断开后移除旧帧、设备重编号和歧义匹配、过期与未来时间拒绝，
以及三路实机采集、页面暂停/恢复和采集进程暂停时的旧帧隐藏。
一次浏览器验证不能证明所有网络条件下的延迟；本方案是低帧率预览，不用于视觉闭环控制。
