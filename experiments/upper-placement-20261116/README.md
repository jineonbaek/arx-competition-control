# 上层双相机放置离线流程

本轮不修改驱动、不启动电机、不获取控制权、不发送夹爪命令。

## 驱动恢复状态

原运行二进制校验值：`aca8d6129b8f1190883bbb4a9e90d48a1858dce860362f319f381abbb00c7d8c`，与切换前一致。原启动脚本仍调用该二进制，未被候选覆盖。这里所称原驱动是原先基于厂家 SDK 的 `x5_controller_web`，不把它称为未经修改的厂家发行文件。

右臂服务保持停止，现场保持急停与独立支撑。反馈候选驱动已退出并撤销执行权限。没有通过重启验证其恢复行为；再次启动原版本仍不能保证保持姿态和夹持。

## 上层流程

1. D435 RGB-D 仓口定位，利用已有 TCP 和电池模型生成左侧仓外目标。回放默认预留 30mm，可通过参数修改；这是本次离线目标，不是对用户强加的固定距离。
2. 严格姿态 IK 不可解时，仅尝试世界 Y 轴 ±1°、±2° 候选，保持目标位置不变并记录选择。不绕过限位或碰撞错误。这些姿态变化尚未实机验证。
3. 输出原驱动已有的 `segment_quintic_scalar` 关节轨迹格式。没有新增驱动反馈依赖，也不伪造内部关节目标或夹爪目标。
4. 原驱动的轨迹完成状态与实测关节到位必须对应同一个驱动实例和命令代次。当前协调器只离线验证这些输入，不能将其等同于实机停止验证。
5. 到位后使用新的 D405 图像及配对的关节/升降反馈，估计竖直偏差，再生成不改变姿态的有限竖直修正轨迹。部分红线识别复用相邻 `d405-disconnected-20261116`。此方法是上下位置微调，不是完整六维姿态估计或自动调平。
6. 不包含入仓、松爪、驱动启动或真实发布接口。所有输出保留 `executable=false`。

## 复用与验证

在本目录中设置 PYTHONPATH 为本目录、相邻 `d405-disconnected-20261116`、原控制工程根目录和其 `web/src`，使用原工程 `.venv/bin/python`：

```sh
python -m unittest -v test_upper_flow test_coarse_retry
python replay.py --capture-dir /path/to/recorded-capture --stand-off-mm 30
```

输入目录须包含原有格式的 `d435.npz` 与 `d405.npz`。相机标定与夹持变换仍为现有估计。回放时间使用历史曝光时间，不将旧帧伪装成当前实时画面。

`replay-report.json` 分开记录粗接近轨迹、模拟到位、旧图拒绝结果和 D405 单模块微调。模拟到位不构成物理证据；本次保存的 D405 图属于接近前，不能完成真实到位后微调的端到端验证。

后续实机接入应复用运行中的控制器，不换底层；还需现场空载启动验证、到位后新 D405 数据，以及带载几何与跟踪误差验证。本轮未部署实机执行入口。
